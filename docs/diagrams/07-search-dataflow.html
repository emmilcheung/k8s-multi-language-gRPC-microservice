sequenceDiagram
    autonumber
    actor C as Customer / Client
    participant K as kong-gateway
    participant TS as ticket-service (Go)
    participant MG as Mongo (ticket_db)
    participant MQ as MSK Kafka
    participant OS as OpenSearch

    %% ----------- PHASE A: Index (CQRS write) --------------------------------
    rect rgb(250,243,219)
    Note over C,OS: Phase A — Index (CQRS write path)
    C->>K: POST /tickets (create or update)
    K->>TS: JWT verified — forward
    TS->>MG: BEGIN txn — INSERT/UPDATE ticket + INSERT outbox row
    MG-->>TS: txn committed
    TS-->>K: 201 / 200 OK
    K-->>C: response
    TS->>MQ: outbox relay publishes tickets.ticket.created or .updated (CloudEvents, key=ticket_id)
    Note right of MQ: Transactional outbox guarantees at-least-once delivery to Kafka
    MQ-->>TS: search-indexer consumer receives event
    TS->>OS: UpsertTicket (external version = Kafka offset, idempotent)
    alt parse error or transient failure
        OS-->>TS: error
        TS->>MQ: route to .dlq + schedule retry (max 3, exp back-off — never silently dropped)
    else success
        OS-->>TS: 200 OK
    end
    end

    %% ----------- PHASE B: Query (read + graceful fallback) ------------------
    rect rgb(234,242,251)
    Note over C,OS: Phase B — Query (read path, with graceful fallback)
    C->>K: GET /graphql TicketsConnection with search filter
    K->>TS: JWT verified — forward
    alt SEARCH_BACKEND opensearch and search query present
        TS->>OS: multi_match query (fuzziness AUTO, boost eventTitle/title/venueName) + filters
        OS-->>TS: ranked ticketIds[]
        TS->>MG: FindByIDs — hydrate canonical data + live availability
        MG-->>TS: ticket docs (authoritative)
        TS->>TS: refill loop — apply ticketType filter, fill page to requested size
        TS-->>K: ranked page (OpenSearch order preserved)
    else Mongo backend, or OpenSearch error / circuit-open
        Note over TS: Graceful fallback — never hard-fails
        TS->>MG: regex search on title and description (degraded relevance)
        MG-->>TS: ticket docs
        TS-->>K: page (Mongo ordering)
    end
    K-->>C: TicketsConnection response
    end

    Note over MG,OS: Availability is hydrated live from Mongo, never from the index. Authoritative gate stays at reservation time.

WORKFLOW SYSTEM FEATURES

  ✅ Status Logging
     → ./workflow.sh status shows complete snapshot
     → Includes service progress, docker state, pause point
     → Read from STATUS.md (single source of truth)

  ✅ Pause/Resume
     → ./workflow.sh pause "message" saves checkpoint
     → ./workflow.sh resume clears checkpoint
     → Checkpoint saved to .workflow-pause file
     → Used to end work sessions and resume later

  ✅ Decision Making
     → ./workflow.sh decision shows 5 service options + recommendation
     → Explains estimated duration and readiness for each
     → Links to detailed descriptions in STATUS.md

  ✅ Docker Monitoring
     → ./workflow.sh docker lists containers and ports
     → Shows connectivity status
     → Can be called anytime to verify infrastructure

  ✅ Checkpoint System
     → 10 predefined checkpoints in STATUS.md
     → From "auth-service complete" to "EKS deployment"
     → Allows pausing at major milestones

  Example 3: Long work session with intermediate pause
  ──────────────────────────────────────────────────────
  $ ./workflow.sh status                    # Check where we are
  $ # Work on order-service for 2 hours
  $ ./workflow.sh pause "order-service 80% complete, transactional outbox done"
  $ # Later...
  $ ./workflow.sh resume
  $ ./workflow.sh status                    # See where we left off
  $ # Resume work on order-service

  Example 4: Switch services due to blocker
  ──────────────────────────────────────────
  $ ./workflow.sh pause "ticket-service: gRPC proto import failed, blocked on buf"
  $ ./workflow.sh decision
  $ # Choose payment-service instead (simpler, no gRPC)
  $ # Work on payment-service
  $ ./workflow.sh pause "payment-service complete, can return to ticket-service gRPC fix"

INTEGRATION WITH LLM SESSION MANAGEMENT

  The workflow system allows:

  1. Pause mid-session
     → ./workflow.sh pause "session checkpoint"
     → Checkpoint stored in .workflow-pause
     → User can exit OpenCode and return later

  2. Resume in new session
     → ./workflow.sh resume
     → Load checkpoint from .workflow-pause
     → Agent can re-read STATUS.md and continue

  3. Full state preservation
     → Docker containers stay running (unless stopped manually)
     → Git commits track code changes
     → STATUS.md documents progress
     → .workflow-pause file holds session context
